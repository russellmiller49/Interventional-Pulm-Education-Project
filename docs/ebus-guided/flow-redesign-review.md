# Guided EBUS flow redesign — implementation review

September 13, 2026. Branch `codex/ebus-guided-flow`, based on `2b10cb6a`. The EBUS feature at that base matched the brief's `c2371c01` content baseline. This implements the attached `EBUS_GUIDED_FLOW_REDESIGN_CODEX_PROMPT.md`; the brief authorizes replacing the old shared three-pane/seven-stage layout.

## Delivered course

All 26 stable lesson URLs now use 114 explicitly authored activities across seven chapters. The course changes presentation for explanation, linked demonstration, acquisition, held interpretation, regional references, written cases, sampling and reporting. Activities vary from three to eight per lesson. Measurement phantoms precede capture in the sole ordering registry. The [coverage matrix](flow-redesign-coverage.md) maps every original objective, teaching field, activity, question, source and limitation to its current presentation.

The host uses stable activity identities and explicit interaction/evidence policy. No numeric stage decides disclosure, task completion or workbench lifetime. The iframe remains in the same React/DOM position from acquisition through held interpretation and feedback; an explicit task/session change creates a new workbench. Demonstrations have separate sessions and cannot record learner acquisition. Back provides read-only review, Help gives the current instruction, and activity changes focus/scroll to the current task. A session-validated resize message sizes the iframe to its content so the page carries the main reading flow.

Shrinking an initialized model task below 768 CSS pixels pauses and hides its workbench without discarding the acquisition. Completion stays blocked at that width. Returning to a supported width requests fresh evidence from the same child/session; the host accepts only observations acknowledging the current `observationRequest`. It never restores cached evidence to make a task appear ready. A model task opened initially on a phone does not initialize the model or earn credit.

Recorded depth, gain/contrast, Doppler and capture now retain actual decoded pixels and provenance. The source includes session/task, clip segment, media time, pixel identity, selected settings and calipers. A hold requires the child to acknowledge its actual paused frame before interpretation opens. The previous comparison is a fixed pixel snapshot until the learner explicitly replaces it. Playback starts only on request, and returning from review remains paused. No model pose is attached to an unrelated recording. Recorded capture does not claim a calibrated clinical dimension or expert border accuracy.

Five revised image interpretations use new `-v2` item identities. The four model knowledge questions now follow guided model application and use `-application-v2` identities. Their original authored objects and first-response keys remain historical. The first-response schema remains backward compatible and records whether instructions were requested in that session. Previous linked skill observations are retained in a bounded per-task history when a new session is recorded; first answers remain immutable. Existing lesson completions and assessment eligibility remain valid, with an explicit notice that they do not prove newly added skills.

## Case records and specimen/report tasks

Three local, versioned artifacts keep source identities separate:

- `case-001-station-seven-window`: a current model acquisition, checked anatomical relationships and the explicit limit of one modeled window. It has no specimen or pathology result.
- `written-node-description-v1`: supplied written sonographic features, unmeasured size and unresolved pathology. It does not masquerade as scored clinical-image recognition.
- `left-lung-workup-v1`: a written examination/specimen case shared by planning, adequacy, allocation and reporting. Two 4R nodes occupy one station and retain separate specimens. The history includes nonrepresentative material, provisional ROSE information, pending final/ancillary results, a representative station-7 sample, an inadequate 4L window and an unexamined 11L target.

Plans, learner declarations, observed model actions and supplied findings have distinct fields/origin labels. No visit or control movement silently marks a station sampled, negative, adequate or completely surveyed. The allocation task accepts laboratory clarification when requirements are absent. The report reconciles each source entry with visualization and sampling fields and preserves reasons, limitations and pending work. No pass counts are supplied or invented.

Artifacts use `ip-ebus-guided-examination:<case>` and do not replace the course progress store. Compatible drafts restore records, never live guidance. Incompatible/corrupt drafts are isolated; starting the current version archives the old bytes before replacement. First record-task submissions are immutable under case/content/task identity. Active lesson acquisition restarts on reload. A workbench reboot/error also cancels a pending hold so acquisition recovery remains possible.

Practice defaults to a versioned coached option with ordinary feedback after each response. Independent practice retains delayed ordinary feedback and its existing keys. Both retain immediate unsafe-choice feedback and first responses. All three optional cases and eight final cases remain available; there is no new passing threshold.

## Implementation boundaries

Root changes are confined to `src/features/ebus-guided`, its tests, the guided bridge and the new recording-source contract. Embedded changes are confined to guided entry/knobology/styles, a small guided-only simulator control gate/status adjustment, and the model-workbench continuation label. The six model packages, geometry, acoustic data, presets, needle constraints, phantom truth and route limitations were retained.

No database, upload, authentication architecture, deployment, public discovery/navigation or other-module migration was performed. Shared lesson-stage defaults remain unchanged. The root course uses its existing generic frame/dialog/verdict primitives; duplicate identical EBUS feedback is suppressed locally. Local source mounts were not edited or copied.

## Failures found and resolved; checks not claimed

[Earlier raw failure outputs](flow-redesign-evidence/earlier-failures.log) are retained separately from the final results. They include early held-image timeouts, the initial contact gate failure, an obsolete stage-test import and an unavailable development preview. The final browser checks use the standalone preview on port 3157.

- The initial contact baseline could arrive after a first movement, making initial/current frame IDs equal. The movement gate now waits for the real baseline.
- Early development/full-page capture runs rebooted a child frame and correctly blocked the held answer. Those runs were not counted as retention proof. Accepted evidence uses stable iframe/session/pixel assertions and viewport screenshots on the production course. Full-page screenshot behavior is not claimed as validated.
- Old tests imported the positional `stageLesson` adapter and expected old tabs. They were replaced with semantic-flow assertions while retaining domain/safety checks. The new browser suite supersedes old shell-selector journeys; historical three-pane scripts are not represented as passing.
- Browser selectors exposed implicit select-label ambiguity in the new record form. Explicit accessible names now identify each field.
- A final root type check caught a Playwright-only `exact` option in a Testing Library unit-test selector. Removing that unsupported option preserved the exact string role query; the corrected check was rerun.
- Visual review found scroll-position drift after task changes and duplicate identical feedback. Focus/scroll and local feedback presentation were corrected; controls are hidden while reviewing held evidence.
- The final playback review identified resume-on-return after an explicitly played clip. Review now clears the playback request; a specific browser regression verifies this behavior.
- The compact-width review identified an iframe unmount below the supported width. The initialized workbench is now preserved and paused; a fresh evidence acknowledgement is required on return. A regression checks the unchanged pixels, session and selected response across 390 → 1440 CSS pixels.
- A coverage-generator top-level-await/CJS error was corrected. The generator now runs with the repository's actual tsx configuration.

Build warnings concern existing large Vite chunks, the Mermaid dependency's dynamic `require`, and the installed Node/tsx deprecation. This checkout has no local Supabase environment: unrelated authenticated navigation/prefetch requests can emit configuration errors in the standalone server log. The unlisted EBUS course/resources and its tested routes function; authenticated-site flows were not claimed as tested or altered. No clinical/faculty/rights approval is inferred from these checks.

## Remaining faculty/owner dependencies

The available registry and reviewed implementation history remain the teaching sources. The official CHEST 2024 summary was checked for context; this work did not perform a complete independent guideline appraisal or introduce universal pass/gauge/medication/handling rules. The brief's cited 2026 ERS source remains in the source registry. `Text.zip`, `Handbook of Endobronchial Ultrasound.pdf` and `EBUS_GUIDED_SOURCE_MAP_AND_REVIEW_FLAGS.md` were not found in the authorized attachment/authoring locations searched; they were not read or treated as supplied source content.

Faculty/source/rights work remains for expert clinical border and axis annotations, pathology-linked image interpretation, reviewed clinical node descriptions, the 4R/10R contrast and additional anatomies, a reviewed cytology/ROSE gallery, device-specific mechanics, media permissions/de-identification, clinical translations, and observed learner review. The new written cases and question revisions also need faculty content approval. These are distinct from the delivered bounded engineering work. The existing [remaining-work record](remaining-work.md) preserves the broader roadmap without marking these dependencies complete.
