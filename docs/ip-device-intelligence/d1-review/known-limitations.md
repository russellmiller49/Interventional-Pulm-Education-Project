# Phase D1 review packet — known limitations

Phase D1 implementation document (2026-08-08). Honest limits of the slice as built; none is a regression against the D0 specification, and several restate limits the specification itself records.

1. **The APC blocking failure cannot fire in the live demo context.** The deliberately-failing `RULE-APC-PLATFORM-FAMILY` rule was moved out of the production seed into `__fixtures__/test-compatibility-rules.ts` before Phase D0 (v0.2, so a real card is never blocked just to exercise a test path); the pinned live rule set holds only `RULE-BALLOON-WORKING-CHANNEL`. The workspace therefore shows the APC chain through the deliberately incompatible demo stand-in fixtures (quoting their own seed rationale) and the balloon rule as a blocking _condition_ that evaluates `unknown` in the live context; the blocking failure itself is proven in `mechanisms.test.ts` by injecting the documented fixture rule into a copied context through the existing resolver — the exact pattern the fixture's docstring prescribes. No second engine and no seed change.
2. **Three readiness states need fixtures to demonstrate.** `missing_room_capability` (the demo location declares every capability the three exemplars can require), `missing_rescue_pathway` (every rescue role has demo coverage), and `inventory_formulary_mismatch` (0 carried rows exist) cannot occur in live data; `readiness.test.ts` exercises each with copied-context or input fixtures, as the D0 specification records for state 8.
3. **`responsibleRole` is null on every authored slot**, so the nursing/technician preview has a single honest "No responsible role recorded" group, subdivided by procedural phase. Populating responsible roles is authoring work, not display work.
4. **es / zh-CN strings are English copies**, following the repository's convention for new untranslated content (same as the `preferenceCards` namespace). Structural parity is test-enforced; translation is later editorial work.
5. **The atlas store is a second in-memory index instance** (not a second implementation): the same statically imported generated JSON, indexed by the same exported `buildCatalogStore`, filtered to the owner's cohort predicate. Memory cost ~753 products of index; the alternative (post-filtering shared-store queries) would leak non-cohort presence through pagination and facet counts.
6. **Direct-link `/[locale]/clinical-roles` (no role code) has no index page** — the D1 route list deliberately includes only `[roleCode]`; the bare path 404s.
7. **Print behavior** was verified to the extent that watermarks are in-flow markup with `print:` border variants; no dedicated print stylesheet was added (outputs are previews, not printable deliverables, in D1).
8. **Dev-environment console noise**: without Supabase env vars, the site-wide analytics endpoint 500s on every page including the new ones. Environment-only; no D1 code touches Supabase.
