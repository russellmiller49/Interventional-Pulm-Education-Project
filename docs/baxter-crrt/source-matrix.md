## 2. Claim and behavior records

The relevant device/math records and Phase 5 pilot evidence records are materialized as strict
TypeScript `SourceReference` values. Reviewer is null for every pilot record and status is pending
unless explicitly changed in a signed later revision.

This is a normalized registry. A complete SourceRecord is the join of:

- The source-registry row, which supplies source title/type/version, market/configuration, document
  limitation, and hash.
- The claim row, which supplies record ID, claim, page/section, implementation location, reviewer,
  and review status.
- The numeric metadata table below, when applicable.
- The conflict table, when a claim references a known ambiguity.

For nonnumeric claims, value and unit may be absent. Device profile/population is derived from the source
ID and claim family: PRISMAX-AW8035-RB maps to prismax-aw8035-2xx; PRISMAFLEX-G5036003-R05 maps to
prismaflex-g5036003-6xx; CLIN records apply to the synthetic adult ICU population; PROTO records
apply only to the named local protocol profile. Phase 2 materializes and validates every active or
explicitly disabled pure-math record; tests reject a missing required field.

## 7. Approval rule

A record may move from pending only when a named reviewer has checked the exact source revision,
page, implementation, tests, units, market/configuration, and learner-facing limitation. Any
consequential change resets that record to pending.
