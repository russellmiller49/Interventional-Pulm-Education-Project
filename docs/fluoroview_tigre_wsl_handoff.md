# FluoroView TIGRE WSL Handoff

## Context

The current FluoroView viewer uses the richer airway model, centerline-derived airway graph,
CT click-to-snap nodule placement, and browser-side scope/nodule overlays. The visual mismatch now
appears most likely to come from one of two places:

- the DRR atlas is still generated by the placeholder CPU ray-sum path, not true TIGRE geometry
- the airway/centerline/DRR coordinate calibration still needs final landmark validation

True TIGRE projection should improve the fluoroscopy anatomy: ribs, spine, mediastinum, diaphragm,
and airway silhouette should look more like a real projection. TIGRE alone will not fix a mesh
transform problem, so the WSL work must include landmark checks after regenerating the atlas.

## Goal For Windows Codex

Implement a real TIGRE-backed `TigreProjector` in WSL, generate a new derived DRR atlas, ingest it
into the FluoroView public case, and validate that the airway overlay, carina anchor, nodule marker,
and scope trace remain aligned across AP, RAO/LAO, and cranial/caudal views.

## Hard Constraints

- Keep raw data outside git:
  - no raw DICOM
  - no raw NIfTI
  - no raw NRRD
  - no STL/OBJ source segmentations
  - no `.npy` atlas arrays in public assets
- Commit/deploy only derived educational assets.
- Preserve the visible safety label:
  `Educational simulation only — not for diagnosis, treatment, or procedure guidance.`
- Local CPU projector and tests must continue to pass without TIGRE/CUDA.
- `TigreProjector` must gracefully fail or skip when TIGRE is unavailable.
- Do not remove the browser-side nodule/scope overlay work.

## Implementation Target

Replace the placeholder implementation in:

```text
tools/fluoroview-pipeline/src/fluoroview_pipeline/drr/tigre_projector.py
```

Current issue:

```text
TigreProjector imports TIGRE, then delegates projection math to CpuRaySumProjector.
```

Required behavior:

1. Convert the CT volume from HU to attenuation coefficients.
2. Create TIGRE geometry from `CArmGeometry`:
   - detector pixels
   - detector pixel spacing
   - source-to-isocenter distance
   - source-to-detector distance
   - voxel spacing
   - volume dimensions
   - isocenter/table offset
   - primary RAO/LAO angle
   - secondary cranial/caudal angle
3. Call TIGRE projection APIs for one or more angles.
4. Return a `ProjectionResult` with:
   - image shape matching `detector_shape / downsample`
   - finite normalized float image
   - metadata backend set to `tigre`
   - geometry metadata sufficient for audit/debug
5. Preserve CPU fallback tests and skip TIGRE-specific tests when TIGRE is missing.

Suggested implementation approach:

- keep `ProjectionOptions` contract unchanged
- add helper functions inside `tigre_projector.py`:
  - `_hu_to_mu(volume_hu, options)`
  - `_build_tigre_geometry(volume_hu, spacing_mm, geometry, options)`
  - `_project_with_tigre(mu_volume, tigre_geometry, angles)`
  - `_normalize_projection(projection, options)`
- add a small synthetic phantom test that compares CPU/TIGRE output shape and gross orientation,
  not pixel-perfect equality

## Atlas Generation

After true TIGRE smoke tests pass:

```bash
conda activate fluoroview-tigre
cd /path/to/Interventional-Pulm-Education-Project/tools/fluoroview-pipeline
python scripts/run_tigre_atlas_job.py \
  --dicom-dir /data/fluoroview/fluoro_2/DICOM \
  --output-dir /data/fluoroview/derived/patient-4/drr \
  --angles "-60,-45,-30,-15,0,15,30,45,60" \
  --cranial-angles "-20,-10,0,10,20" \
  --detector-sizes 1024 \
  --backend-label tigre \
  --provenance-note "Generated with true TIGRE projection geometry on local WSL NVIDIA GPU. Educational simulation only."
```

Then ingest only derived display assets into the repo:

```bash
cd /path/to/Interventional-Pulm-Education-Project
PYTHONPATH=tools/fluoroview-pipeline/src python tools/fluoroview-pipeline/scripts/ingest_drr_atlas_export.py \
  --atlas-dir /data/fluoroview/derived/patient-4/drr \
  --case-dir public/fluoroview/cases/patient-4 \
  --backend-label tigre \
  --flip-vertical \
  --tone-map fluoro
```

If anatomy is inverted or mirrored, do not guess silently. Capture validation images and try the
minimal display-plane correction:

- remove/add `--flip-vertical`
- if needed, add an explicit horizontal flip option to the ingest script with manifest provenance
- update browser projection math only if detector coordinate convention is proven wrong

## Alignment Validation

- centerline carina from updated airway graph
- carina on AP DRR
- tracheal midline
- right/left mainstem takeoff
- vertebral column midline
- clavicles/shoulders on AP

In the browser, verify:

- `/fluoroview` loads without console errors
- airway overlay carina sits on fluoroscopic carina in AP
- RAO/LAO slider changes are continuous and the overlay moves with the atlas blend
- cranial/caudal movement keeps the airway, nodule, and scope markers in the same detector geometry
- CT click snaps a nodule and updates scope route
- nodule marker appears on CT and fluoro
- scope tip/trace follows the selected route
- safety label remains visible
