# CT-first branch tracing flow

Implemented from the September 13, 2026 owner brief, on `codex/branch-tracing-flow-redesign`. The canonical entry remains `/en/learn/anatomy/branch-tracing`. This is an ungraded, unlisted educational preview using one teaching CT. There are no release, access, source-asset, database or shared-stage changes.

## Baseline and scope

Implementation started from current `origin/main`, `2b10cb6a` (PR #192), rather than resetting to the brief's reviewed `8e16b69c`. The working tree was clean. Current main already contained `c6-local-teaching-r1`, nine lessons, local exercises, coached Practice, draft restoration, a rendered orientation introduction, and recent improvements to branch-mark progression. Those capabilities were preserved.

The remaining problems were the opening dependency order, repeated orientation/parent-map requirements across different tasks, the absence of a fixed same-image comparison, generic walkthrough captions, disconnected or buried route maps, and full routes that still used the permanent Steps/Teaching/Simulator layout. The new brief supersedes those historical layout requirements. No sibling feature or shared presentation API was edited.

Baseline focused Jest result: 42 passed, one existing access assertion failed at `contracts.test.ts:201`. It expects `/airway-anatomy/case-001/case_manifest.json` to be private, while current main's access helper returns public. This change neither modifies that helper nor weakens the assertion. See [validation](flow-redesign-validation.md) for final results.

## Task-specific screens and controls

`LocalCtLesson` and `CtRouteWorkspace` compose the existing public `LessonShell`, header, task card and help dialog. Local tracing keeps the task beside the native image. Viewpoint teaching replaces that image area with a fixed standard reference and a controlled comparison copy. Parent application places its explicitly oriented schematic alongside the CT. Short and complete routes give the evolving map its own review surface. Narrow layouts bring the image before longer supporting material; enlarged text uses document flow.

The observer schematic fixes the patient and holds anterior at the top of both cross-sectional references. Its feet-to-head CT observer and distally directed central-airway observer are explanatory references. Reflection changes the comparison display only; it does not turn CT into bronchoscopy or manipulate the actual camera. Upper-lobe conventions are introduced later as optional regional aids.

Controls distinguish CT slice browsing, response-slice selection, marking, checking, comparison and task continuation. A mark or a correct comprehension choice never advances automatically. `Return to standard axial`, `Reset attempt`, `Restart lesson` and returning to a parent slice remain separate operations. Keyboard marking, neighboring-slice keys, manual demonstration steps, repeat comparison and reduced-motion use remain available.

## Source correspondence and route scope

The generated [coverage/annotation manifest](flow-coverage.json) derives all nine entries from the runtime registry. It records source hashes, selected intervals, ordered demonstration frames, model-locator captions, parent/daughter source edges, response planes/restrictions, provisional review status, task support and draft impacts. Regenerate or check it with:

```sh
npx --no-install tsx scripts/branch-tracing/flow-coverage.ts
npx --no-install tsx scripts/branch-tracing/flow-coverage.ts --check
```

Per-example captions distinguish source geometry from visible CT evidence. No centerline-distance accuracy predicate was introduced. The software can establish source membership and topology; it cannot establish that a lumen or separating wall is clinically resolved on every plane. Backtracking and uncertainty remain valid responses.

The short map traverses parent edges 10 → 23 → 50 to nodes 11 → 25 → 52. Source-topology checks confirm no fork is omitted within that declared LB6 interval. The first walkthrough separately follows the LLL approach from slice 332 toward the LB6 origin near 321, then turns cranially to the LB6 parent at 325. That prelude makes the direction reversal visible without falsely crediting a skipped proximal decision.

Local point selection now ranks multiple intersections on the same edge against its source anchor. CT/virtual pairing first restricts candidates to the active parent/daughter edge interval, then ranks their position along that interval. A nonintersecting plane reports separation instead of claiming registration. Existing source CT, graph, manifests, nodule patches and camera-roll definition are unchanged.

## Modes, response history and drafts

Learn demonstrates before new application and offers immediate comparison. Practice still defaults to one coached route; the existing segment selector and mixed sets remain. Assess withholds reference marks, keyed path labels and model-route camera cues until the independent set is submitted. Its recorded map uses neutral daughter labels. Exploration is optional and does not award lesson completion.

Maps show only recorded relationships, retain siblings, separate the learner's selection from the model continuation and label unresolved choices. Continuing after an uncertain/different choice follows the authored source route explicitly. This is not adaptive instrument navigation. Recorded divisions can be reviewed without resubmitting; junction retries retain first responses and are marked as supported after comparison. Read-only response snapshots are available on the underlying CT. Worksheet exports retain attempts and the one-source-CT disclosure.

Fresh displays start standard axial. Retry/restart/next-example policies are explicit; a regional convention is learner initiated after explanation. Compatible transformed drafts restore native marks and viewing state with a notice and reset. The existing envelope and participation store remain in use. `observer-comparison-r2` versions only the new orientation activity; historic orientation participation remains visible and unrelated completion is retained.

Known baseline local signatures are accepted where response geometry remains compatible. Old support defaults to `legacy-unknown`. Integration requires course interpretation for newly recorded responses, while an already recorded compatible legacy comparison remains history. Incompatible or damaged drafts are preserved under the existing draft key's `.recovery` suffix before replacement; failure to preserve or save shows an explicit leave-without-saving choice. Full-route drafts conservatively default missing target-inspection metadata; viewing a valid target is required before a new distal interpretation can be submitted.

## Review still required

The manifest names five gaps: faculty CT lumen/wall review (G1), parent-opening review (G2), additional reviewed variant examples (G3), unfamiliar-patient evaluation (G4), and first-time-learner/educational-outcome evaluation (G5). None was performed or implied by software tests. Existing Kurimoto–Morita nomenclature and figure associations are retained; this implementation did not independently reread the full textbook or introduce an alternative clinical method.

An instructor can review the full opening sequence, all pattern intervals, short map, complete route and saved work using the routes in [the validation handoff](flow-redesign-validation.md). A completed worksheet records participation and comparisons, not instrument reach, bronchus sign, tool-in-lesion, diagnostic yield or procedural competence.
