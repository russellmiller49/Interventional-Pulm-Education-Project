## Shared integration slices

Neither is required for BF-03's acceptance evidence; both are recorded so a later owner decision can serialize them.

1. **"Integration capstone" group label.** The shared `SectionsDrawer` → `PathwayNav` prints "Integration capstone" (and ", integration capstone" in its accessible name) for any pathway section whose stage is `'integration'`; `stageLabel` in `learning-module/curriculum/types.ts` does the same for `PathwayLanding`. Foundations passes `'integration'` for "Report and handoff" and "Training records" from `BRONCH_SECTION_STAGE`, which its pedagogy validation also uses. The label names a group and makes no mastery or competence claim, but "capstone" is vocabulary Foundations' own hub test refuses. A neutral label is a shared change affecting every stage adopter; relabelling the stage inside Foundations would misstate its pedagogy. Proposed slice: a shared label change with consumer tests for each adopter.
2. **Sections without a first check.** The four combine proposals in the ledger (`Q27`, `Q26`, `Q19`, `Q04`) remove a section's `check` step. `predictionStepIndex` then feeds the shared stage's step visibility (`learning-module/stage/stageModel.ts`) and teaching disclosure (`StageTeachingScope`), and Foundations' own `BronchStageHost`, `stageSession` and lesson validator. A Foundations-local rule for which step opens after-commitment teaching when a section has no first check would avoid editing the shared stage, but it changes disclosure in four sections and needs faculty for two clinical carry-overs. Not implemented; see the [ledger](BF-03-question-ledger.md#the-four-combine-proposals-and-why-bf-03-did-not-implement-them).
