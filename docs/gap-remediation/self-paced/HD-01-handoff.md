# HD-01 — ICU Hemodynamics self-paced conversion: handoff

## Delivery and scope

HD-01 converts the public ICU Hemodynamics module (`src/features/icu-hemodynamics`, routes under `src/app/[locale]/icu-hemodynamics`) to the self-paced contract in [README](README.md). Work is on branch `claude/hd-01` in worktree `…/Interventional-Pulm-Education-Worktrees/claude-hd-01`, cut from `origin/main` at `5d21844f` (merge of PR #206); the checkout was clean before the task. The historical external-review baseline `9ef04539` is an ancestor of that head, and `git log 9ef04539..5d21844f` shows no commit touching the hemodynamics feature or its routes — the reviewed files were the starting files, and nothing newer existed to preserve or reset.

The v2 `LEARNING_DESIGN_BRIEF.md` and prompt `HD-01.md` from `/Users/russellmiller/Projects/Interventional-Pulm-Local-Data/roadmaps/IP-Education-Self-Paced-Action-Pack-v2/` (read in place, not copied) govern this slice. They supersede the older hemodynamics records that required commitments before teaching, a five-correct recognition standard, first-response tallies, a masked challenge and mastery writes (`docs/critical-care/hemodynamics-flow-rebuild.md`, `hemodynamics-learner-review-record.md`, the critical-care activity contract). Those records stay as history.

**Module-local only.** No file under `src/features/learning-module`, `src/features/critical-care`, `src/lib` or `src/features/device-intelligence` changed (`git diff --name-only` checked). Device Intelligence was not audited or touched. At the time of this work `codex/track-a-crrt` had uncommitted edits to the shared critical-care progress files (`content/activities.ts`, `progress/index.ts`, `progress/publicClient.ts`, `progress/publicAccountSync.ts`, `progress/adapters/crrt.ts`), so the shared hemodynamics projection is identified below as a separate serialized slice rather than changed here. No dependency, backend, grading service, Supabase/upload command, deployment, publication or remote data change was made.

## Progress, storage and legacy records

- **New:** `icu-hemodynamics-self-paced-v1` (`engine/selfPacedProgress.ts`) = `{ version: 1, visitedSectionIds, reviewedSectionIds, openedCaseIds, location: section | case(practice|applied) | null, updatedAt }`, strict schema, no answers, scores, attempts or hints. An unreadable stored value is left in place (learning continues with an empty record); a refused store returns `false` without interrupting learning.
- **Legacy, read-only and byte-preserved:** `icu-hemodynamics-learn-v1` (parser only), `icu-hemodynamics-progress-v2` and `-v1` (parse and in-memory migrate only; the reader, writer, result recorder and mastery helper are deleted), and the normalized `critical-care-activity-progress-v1`, which HD no longer reads or writes. A structural test fails if any module file other than the record and its hook touches storage, or if a grade/normalized writer or response event reappears.
- **Dormant compatibility scoring:** `calculateHemodynamicScore`, `hasHemodynamicMastery` and the score set by `COMPLETE_CASE` stay inside the reducer (engine tests use them). No component displays, writes or branches on them.
- **Analytics:** module code no longer calls any recorder. `useCriticalCareActivityAnalytics` still emits its automatic `activity_opened`, `qualified_start` and `phase_completed` events (the browser run saw `/api/analytics` return 401 for the unauthenticated local session).
