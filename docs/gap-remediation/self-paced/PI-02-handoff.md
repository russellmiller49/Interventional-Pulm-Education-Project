## Privacy and tracking findings

- **Site usage tracker** (`src/components/analytics/SiteUsageTracker.tsx`, mounted in the locale layout) already sends session start, a 30-second heartbeat and end, with module id, route, duration and a random session id, for Imaging routes. `/api/analytics` returns 401 without a signed-in user and otherwise stores the events against that user. PI-02 changes nothing here. The plan runs sessions signed out in a fresh profile, so nothing is stored and the facilitator reads no analytics.
- **Module beta feedback** (`src/features/module-beta`) needs a signed-in, verified account and stores the tester's email, page path, comment and optional screenshot. It is not pseudonymous, so it is not the session record. Its safe-path key list does not include `section`, so an Imaging Learn address would be stored without its section. Noted as context; not changed.
- **Imaging progress** is local to the browser and holds no answers (PI-01). No export exists or was added.
- No backend, analytics service, score export, assistance tracking, recording tool or participant store was introduced.
