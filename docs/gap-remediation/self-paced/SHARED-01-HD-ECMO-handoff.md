## Teaching reveal and genuine operations

`src/features/learning-module/components/ScenarioTeachingDebrief.tsx` previously returned only a working-frame textarea until `capturedFrame !== null`; capture required nonempty trimmed text. This state is local React state, with no simulator event, measurement, acquisition, persistence or completion callback. Its only production caller is HD's `HemodynamicCaseActivity.tsx`.

Added optional `allowRevealWithoutFrame` (default false), enabled only by HD. A separate `teachingRevealed` boolean opens the teaching on request. It never sets `capturedFrame`, copies the draft, dispatches an action or calls `onContinue`. The revealed view says **No working frame recorded**. Actual text capture and the shared default behavior remain available. HD-01's existing direct expert-reasoning disclosure is retained.

No balloon, flush, wedge-validity, thermodilution, measurement/capture, real line-repair, ECMO interlock, sensor-validity or observation predicate changed. HD rendered coverage verifies reveal leaves the actual reassessment unrecorded and storage unchanged. Existing HD safety/action tests and ECMO device/model tests remain in the module regression run.

## Historical data treatment

- Shared reads, projections and hydration do not rewrite/delete/migrate HD V1/V2, ECMO historical envelopes or normalized records. Tests use deliberately formatted JSON and verify exact stored strings survive both public and restricted account-sync mounts.
- Old server responses remain unchanged; filtering produces a current view, and old HD/ECMO completion is never POSTed. Account tests mock authentication and GET responses; no real account or backend is contacted.
- Subset merging refuses replacement HD/ECMO rows and resume pointers. Other catalog subsets still reconcile through the existing implementation, preserving historical rows in the full envelope.
- Historical adapter results are diagnostics, not current learner progress. Existing module parsers and raw normalized export remain available for reading history. No old scores are converted to `visited`, `reviewed`, self-paced location or completion.
- ECMO's pre-existing module-local visit writer can append its `selfPaced` field to the existing envelope, as documented in ECMO-01. This PR does not change that writer or claim whole-envelope byte identity across such a new module visit. Shared read/hydration preservation and module-local historical-value preservation are distinct contracts.
