## Reading-inventory method and test quality

The script walks each Learn step, treating individual pathway-walk stops as separate screens, without answering. Words are whitespace tokens containing a letter or digit. “Primary summed” counts arrival-visible text on every screen, so repeated text is counted repeatedly. “Primary unique lines” deduplicates exact normalized lines within each section, then sums sections. “Optional unique” similarly counts closed-details content and available explanation text, excluding exact lines already counted as primary. “Repeated-line extra words” counts extra appearances of lines of at least eight words on at least three screens. SVG labels/DOM text and live numbers can affect exact-line identity; these counts are not stable measures of conceptual uniqueness. Selected-option text and display:none content are excluded; screen-reader-only text is reported separately.

The final repaired/integrated inventory still covers 78 screens/68 steps: primary summed **58,253**, primary unique-line **30,544**, optional unique-line **38,576**, repeated-line extra **14,597**. Section 9 is **2,421** on the first screen and **7,727** across the section. The visible source hold increases default-path words relative to the submitted head; the repaired path remains substantially below the authorized base. The first final-inventory attempt lacked its output directory and stopped after the first section; the complete rerun succeeded after the directory was created.

The default path is clearer but not brief: large optional references are still repeated beside several Section 9 tasks, and the first screen still has more than 2,000 words. Native closed disclosures keep their payload out of the effective accessibility tree until opened. Essential interpretation limits must not be sacrificed to reduce words; the repaired visible source notice deliberately adds default-path text.

Some of the 88 submitted tests check useful behavior (skip/retry/storage, actual case state, device configuration), but source-map labels/locator shapes and self-referential content comparisons cannot establish source truth. They were not accepted as evidence that a PDF said something. Independent PDF/DOCX inspection, actual base/head data equality, state replay, seven initial failing regressions, unknown-action tests and real browser journeys provide the missing evidence. The new MCS tests call cleanup and restore real timers; unchanged interval effects clean up on unmount. Grouped `--detectOpenHandles` found no open handles. There is no demonstrated cross-suite MCS timer/server leak.
