# BBT-02 — Bronchial Branch Tracing: junction feedback and optional naming

**Completed scope:** Bronchial Branch Tracing only (`/learn/anatomy/branch-tracing`, the local CT lessons). After a learner checks their daughter marks, the comparison now reports where each mark sits against the model locators on that slice, in millimetres, and, for five pilot junctions, explains where the two paths diverge, which wall or lumen decides identity, which adjacent slices to revisit, what to look for after an unresolved response, and the daughters' names with a short demonstration and an optional, unrecorded try where the name follows lobar or segmental anatomy. It follows [the active contract](README.md), the [BBT-01 handoff](BBT-01-handoff.md) and the BBT-02 prompt. **No clinical approval, release, publication or deployment is claimed or performed.** The [five-junction packet](../bbt/BBT-02-junction-packet.md) is NOT REVIEWED. The shared lesson stage, critical-care catalog and progress code, site access lists, other modules and Device Intelligence are unchanged.

## Junction selection and what was actually read

The five junctions (all existing local-lesson divisions) and the reason for each are in the packet's selection table: junction-1 (trachea → RMSB / LMSB, the easy central division), junction-6 (LLL → LB6 / basal trunk), junction-10 (RML → RB4 / RB5, in-plane), junction-14 (RB1 → RB1b / RB1a, the difficult subsegmental choice) and junction-20 (RB5 → RB5a / RB5b, partial-volume samples). For each, the authoring session read the shipped native-v1 axial PNGs at the parent, node and daughter slices with the model edge crossings drawn (contact sheets in the evidence folder), and the parent/daughter references, edge spans and source HU samples from `branch-decisions.json` and `paired-routes.json`. The annotation status of every locator remains `provisional`; the packet records that, and the RB1a/RB5a/RB5b samples' lower air density, explicitly. No sentence from the synthetic phantom exercises (`content/phantoms.ts`) was reused; a jest contract asserts it.

## Predicates and gates

No predicate changed. `check` keeps its real preconditions (every mark or uncertainty, course/branch where asked); `skip`, `next`, `retry` and the parent view are as in BBT-01. The feedback is a pure function of the checked attempt's marks; it introduces no gate, no lock and no recommendation. Authentication, unlisted/noindex access and coordinate identity are untouched.

## Feedback design against the prompt

| Requirement                                                                 | How it is met                                                                                                                                                                                                  |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Explain where selected and intended paths diverge                           | Packet `divergence` cites the model node slice and the slices on which the lumens separate (or, for junction-1, that they do not separate within the browsable interval)                                       |
| Which wall/lumen continuity matters                                         | Packet `continuity` per junction, from the actual slices (side of midline; posterior extension without a resolved wall; in-plane wedge; ring → waist → wall; thin lumens beside vessels)                       |
| Which adjacent slices to revisit                                            | `revisit` intervals with Go-to-slice buttons; a jest contract keeps every slice inside the exercise's browsable range and one interval around the model node                                                   |
| Geometric mismatch ≠ reason                                                 | The sentence reports distances and "sits nearer X"; the note and each `whenNearer` text say the geometry cannot say why; no "you mistook/confused" wording (asserted)                                          |
| No vessel-for-airway assertion from a point                                 | Stated in the note; junction-14/-20 teach how to tell a lumen from a vessel without attributing it to the learner                                                                                              |
| Ambiguous/unreviewed anatomy → explicit uncertainty and faculty review      | `uncertain` list per junction, subsegmental naming shown with uncertainty and no try, HU notes, "authoring reading" attribution in the UI and packet                                                           |
| Uncertainty as a starting point; reference trace; retry or continue         | "Uncertain? Start here" with `moreEvidence`; walkthrough replay on every comparison; existing Redo marks and Continue; "neither counted against you nor turned into an identification"                         |
