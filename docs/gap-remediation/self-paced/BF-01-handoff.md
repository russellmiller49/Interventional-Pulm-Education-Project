## Progress, storage and legacy records

- **New:** `ip-bronchoscopy-foundations-self-paced-v1` (`engine/selfPacedProgress.ts`) = `{ version: 1, lastSectionId, visitedSectionIds, reviewedSectionIds, reviewLaterSectionIds, surveySnapshot, updatedAt }`, strict schema; unknown and repeated section ids are dropped on read. Writes: opening a section, the reviewed mark on Finish (and its undo), the review-later toggle, and the survey when genuinely finished. A refused store shows the existing storage alert and learning continues. `useBronchoscopyFoundationsRecord` now reads this record.
- **Earlier record, read-only and byte-preserved:** `ip-bronchoscopy-foundations-v1`. `engine/learnProgress.ts` keeps the schema, `parseBronchRecord`, `readBronchRecord` and `isSectionCompleted`; every writer is deleted. Its completions, first attempts, support labels, performance summaries and debrief timestamp no longer appear and do not seed the new marks. Only a finished survey saved under it can still feed the report exercise. The nine-module course key `ip-intro-bronchoscopy-progress-v1` is still not read.
- **Boundary test:** `self-paced-boundary.test.ts` fails if any module file other than `selfPacedProgress.ts` writes storage, if a retired grading, first-answer or completion identifier reappears, or if anything but the record modules imports the earlier record.
- **Dormant:** `microCaseAttemptKey` and `capstoneAttemptKey` (legacy key format only). No scoring remains in module code.
- **Analytics:** unchanged; the module calls no response recorder.
