## Follow one airway: authored for its intervals

Before, the lesson was `{ ...continuity, … }`. It inherited the bifurcation lesson's `teaching`, `worked` ("In the right-upper-lobe example, the route first descends in the right main bronchus and then turns cranially…"), `interpretation`, `transferPrompt` (bronchus intermedius → RB5), `sourcePages` and trace metadata (`right-upper-entry`, `middle-lobe-entry`). The RUL worked text reached learners through "Earlier teaching and regional worked example". The actual exercises are two same-lumen intervals, taken from `localExercise` rather than restated:

| Interval | Source trace / junction      | Parent airway         | Slices (0.5 mm)            | Display        |
| -------- | ---------------------------- | --------------------- | -------------------------- | -------------- |
| 1        | `central-right`/`junction-1` | Trachea, above carina | 416 → 412 (4 caudal steps) | Standard axial |
| 2        | `central-left`/`junction-3`  | Left main bronchus    | 352 → 348 (4 caudal steps) | Standard axial |

Every field is now explicit: objective, prerequisite, concept, a two-sentence **clinical purpose** ("A CT route to a peripheral target is built one slice at a time. If a single step jumps to a neighboring airway, every branch decision after it is made on the wrong route."), two teaching paragraphs, a visible four-item **tracing checklist** (demonstration and attempt), worked text naming both airways, the direction and "four 0.5 mm steps (2 mm)", an interpretation of the comparison, and the transfer prompt for the LMSB interval. The trace metadata now reads `example` and `prediction` `central-right`, `transfer` `central-left`, matching the demonstration, first try and repeat. The source-page field reads "Chapter 1 · page reference pending review" (see holds). A jest contract ties these words to the geometry: airway codes, a 4-slice caudal interval (LPS z falls with the slice number), 2 mm length, no upper-lobe, RB5 or intermedius text, and no paragraph shared with the bifurcation lesson.

Standard axial is kept. The interval reducer still rejects every display transform in a same-lumen lesson, even after a convention was explained elsewhere; the "Begin with standard axial CT" explanation (patient R on screen-left, A at the top) still precedes tracing.

## Progress, storage and legacy records

- **Current record:** `branch-tracing.self-paced-v1` (`engine/selfPacedProgress.ts`, strict zod). Fields: `version`, `lastLessonId`, `visitedLessonIds`, `reviewedLessonIds`, `reviewLaterLessonIds`, `displayExplanationsShown`, `updatedAt`. It holds no marks, branch choices, answers, correctness, hints, attempts or support labels, and a record carrying any extra field fails to parse. Writes happen on opening a lesson, reaching the end of a lesson (or Undo), toggling Save for review, and when a display-convention explanation is shown. Unchanged state is not rewritten; an unreadable value is left byte-for-byte and nothing is written over it.
- **Drafts** (`branch-tracing.draft.*`, `engine/ct-draft.ts`) still hold the learner's own marks, choices, CT slice and view so a lesson or route set resumes. The eight local lessons' draft signatures are byte-identical to baseline (asserted). The route lesson signature changed only because step gate metadata is part of it; `ROUTE_DRAFT_ALIASES` accepts the recorded pre-change signature, and `parseRouteDraft` still validates every response. `reached` defaults to 0. Legacy `support`, `hints`, `orientationResponses` and `viewAnswers` values in drafts still parse and are kept, never shown or appended.
- **Legacy participation** in the shared `critical-care-activity-progress-v1` envelope (`branch-tracing.c6-local-teaching-r1.*`: lesson visits and completions with resume, orientation-check completions per preset, `*.trace.first` with `hintCount`, older `*.connectivity.first` / `*.viewpoint.first` with `bestScore`) is no longer written, read for navigation, or shown. The writers `saveVisit`, `saveFirst`, `saveBranchFirst`, `saveCtAttempt`, `saveOrientationUnderstanding`, `recordFirst` and the reader `learnedOrientations` were removed; `completedLessons`, `hasHistoricalOrientation` and `progressVersionChanged` remain as pure readers. A structural test fails if any BBT source writes or references the shared envelope, imports the legacy module, or writes storage outside `selfPacedProgress.ts`, `ct-draft.ts` and the existing Practice segment preference.
- **Telemetry and accounts:** BBT makes no analytics or network calls and has no account sync; nothing was added.

## Legacy-progress implications

- A learner with legacy BBT completion keeps those bytes, but the Overview no longer shows "Completed", the old notices, or a door computed from them. The recommendation starts from the self-paced record, so for them it starts at Follow one airway until they open or finish lessons. Showing legacy completion as opened would be a separate owner decision; it was not done because the owner asked that old progress not become new self-paced progress.
- Earlier, a legacy orientation-check completion skipped the display explanation for that preset in later lessons. Now each device shows each explanation once (`displayExplanationsShown`), without converting the legacy result.
- Nothing deletes, migrates or rewrites legacy data, including unknown fields in drafts.
