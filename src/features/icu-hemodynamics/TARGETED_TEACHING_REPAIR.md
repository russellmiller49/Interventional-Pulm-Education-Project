# ICU hemodynamics — targeted teaching repair

Implemented locally on `codex/icu-hemodynamics-9-13`, from the clean reviewed baseline `ab05b9d6`. The supplied prompt served as the feature specification. The intended learner is an early pulmonary/critical-care fellow familiar with basic cardiac anatomy and ECGs but new to PAC monitoring. Completion records educational work, not clinical competence.

## Before and after

The baseline already included the normal RA→RV→PA→PAWP walk and a clean pressure-system opening. Both are retained. Baseline findings below were verified in source and tests; they are not presented as a retrospective browser audit.

### Limits

- The initial default Turbopack attempt failed on generated CSS parsing. The repository’s normal webpack setting compiled and served the tested routes successfully.
- This isolated server has no configured analytics database credentials; analytics requests fail locally. Event semantics and completion uniqueness were tested in the feature, but remote analytics persistence was not verified.
- The full production build was not run; its script builds unrelated training apps and assets beyond this assignment. No deployment, commit or push was performed.
- These checks establish rendered behavior and regression coverage, not novice usability, accessibility certification or clinical validation. Narrow/zoomed layouts require panel scrolling.

## Faculty review and instructor walkthrough

Clinical changes remain draft. Review the illustrative equal-MAP/different-output vignette (60 mmHg; 2.8 versus 7.0 L/min), the clinical-measurement category for method-derived thermodilution output, and sampling versus saturation versus calculated oxygen content. Existing sort keys are unchanged. The independent atrial example translates the normal authored baseline by 2 mmHg and renumbers regions; it is not a new disease model. Review atrial timing caveats and the contextual interpretation of existing abnormal atlas shapes. The procedural safety prebrief retains its existing qualifications.

The existing source records and morphology data remain the content authority. [The registered PAC placement/waveform review](https://link.springer.com/article/10.1007/s10877-021-00662-8) was consulted for terminology and reference setup. No transcript was used as a treatment guideline. No new visual asset is required; all teaching and question figures reuse existing data.

1. Start from Overview. Read measurement origins and the pressure/flow worked example. Choose the underfilling explanation on the first vignette to inspect wrong-answer feedback. Continue to the separate worked classification and then the seven independent rows.
2. In Pressure system, walk the clean setup, then adjust height, zero at the reference level, change only the ART scale, and view the three labeled release responses. In the combined fault, correct level/zero, acquire and classify the abnormal flush, apply the simulated correction, and observe the labeled old capture. A fresh completed acquisition and correct classification enable comparison. Repeat in the different transfer case.
3. In Chamber recognition, walk all four locations and compare RV with PA. On the unknown live tracing, choose PA to inspect feedback on the RV example. In recognition, include an error: the correct count remains cumulative. After five correct responses, apply the interpretation to the different visual model example.
4. In Atrial components, select each labeled explanation. In the guided a-wave task, choose Region 2 first, then retry with Region 1; assistance is recorded. Complete the new renumbered example. Reset an exercise and verify that first-response evidence remains. Study the abnormal contrasts, answer a mechanism question incorrectly, and inspect the matching trace/feedback. Complete transfer and reload: section completion persists while the section reopens at its first step.
5. Open the two procedural links. Read the existing prebrief/sequence before the first question. The essential lesson remains available when 3D loading fails.

Instructor acceptance is still the supplied question: can a new fellow explain which signal is shown, why it looks that way, what action is available now, and what completion established without interface coaching? This implementation makes that review possible; it does not claim that a fellow has passed it.
